# quadrable WordPress Scenario

Authenticated local-first state sync for Playground snapshots and content databases.

## Current Native Slice

Pure-PHP BLAKE2s-256 hash/key primitives plus an in-memory sparse tree for get/put/delete, update batching, path-independent roots, `getMulti`, upstream-shaped raw-key `getMultiRaw`, `FullKeys` proof transport with tracked string-key enumeration, direct upstream `big proof test` 1000-query proof/import/getMulti behavior, empty-head restoration, delete bubbling equivalence, ordered raw integer keys for WordPress option/post records, PHP-native large integer key overflow rejection, composite integer/hash keys for post-meta style rows, an exact upstream-digest snapshot root, iterator windows for incremental sync chunks, compact authenticated range proofs for partial snapshot verification, delegated sub-range proofs exported from already imported partial range proofs, shared empty witness proofs for multiple absent keys in the same empty subtree, proof-backed partial-tree updates for narrow content changes, merged partial proofs for independently requested records, delegated sub-proofs exported from already imported partial proofs, bounded sync proof fragments with diff reconstruction, upstream-compatible sync fragment path-order/same-path guards, scan-time diff callbacks that match the final authenticated diff, imported proof-fragment shadow leaf node ids that match final sync diffs, exposed memStore-range sync shadow root node ids, upstream-MT19937-shaped sync-fuzz dimensions and byte budgets, full native upstream-shaped sync-fuzz convergence, full persisted tracked-node snapshot sync-fuzz convergence, cached full proof-tree reuse for repeated proof-fragment export, partial-shadow diffs that skip unchanged witness branches while reconstructing changed paths, tracked leaf node-id reuse for compact rebuilds of unchanged snapshot records, saved branch-head checkout for old/new snapshot forks, tracked node-store snapshots that reload named heads and branch node ids from JSON, tracked scan/final diffs that report identical leaf node ids for changed/deleted/added records, tracked diff application that reconstructs changed snapshots from final diffs, memStore-range detached overlays for volatile preview edits, named published heads that reject volatile MemStore writes until a preview fork detaches the head, native file-backed `quadb`-style current-head reloads for WordPress snapshot previews, upstream-shaped tracked string-key `quadb diff`/`patch` lines for applying preview edits to another WordPress snapshot head, file-backed `quadb exportProof --hex` FullKeys proof bytes for delegated preview reads, file-backed `quadb importProof --hex`/`mergeProof --hex` proof-backed heads that persist delegated partial reads across reopen, and file-backed proof-head string-key writes/deletes/forks that replay across reopen and can export updated delegated proofs.

## Fixture And Example

- `fixtures/wordpress-ordered-snapshot.json` stores ordered `wp_options`, `wp_posts`, and `wp_postmeta` records under raw integer keys.
- `examples/wordpress-iterator-window.php` loads the fixture and emits a three-record window beginning at key 2, modeling a bounded Playground snapshot sync page.
- `examples/wordpress-raw-multiget.php` batch-reads raw integer WordPress snapshot keys, including an absent record id, without rehashing already encoded sparse keys.
- `examples/wordpress-full-key-proof.php` exports a `FullKeys` proof for string-keyed WordPress option/post records, imports it, and enumerates only the authenticated original keys present in the partial tree.
- `examples/wordpress-large-proof-window.php` maps the upstream big-proof shape to a 1000-key WordPress post snapshot window, proving 500 existing post IDs and 500 missing external IDs while leaving an unproven next post unavailable.
- `examples/wordpress-integer-key-boundary.php` writes the largest PHP-native sparse integer key and shows that the next ID is rejected with the upstream-shaped `int range exceeded` guard.
- `examples/wordpress-composite-meta-key.php` uses `Key::fromIntegerAndHash` to group multiple hashed `wp_postmeta` names under a stable post-id prefix.
- `examples/wordpress-proof-range.php` exports and imports a compact range proof for keys 2 through 4, then reads the authenticated partial tree using only the trusted root and encoded proof bytes.
- `examples/wordpress-sub-range-proof.php` imports a wider range proof, exports a narrower delegated range proof from that partial tree, and verifies that a record outside the delegated range remains unavailable.
- `examples/wordpress-proof-update.php` exports a narrow proof for a single `wp_posts` record, applies an authenticated update to the imported partial tree, and verifies that the partial update root matches the full snapshot update root.
- `examples/wordpress-proof-merge.php` imports one proof for `siteurl`, merges a second proof for a post record with the same trusted root, and reads both records from the expanded authenticated partial tree.
- `examples/wordpress-sub-proof.php` imports a wider option/post proof, exports a narrower delegated sub-proof from that partial tree, and verifies that a record outside the delegated proof remains unavailable.
- `examples/wordpress-sync-diff.php` uses upstream-shaped sync request/response transport round trips to fetch bounded proof fragments from a changed snapshot, diff the authenticated shadow tree, and reconstruct updated/deleted/added WordPress records locally.
- `examples/wordpress-sync-scan-diff.php` streams scan-time diff callbacks while sync requests converge, then shows that those callbacks match the final authenticated WordPress option/post diff.
- `examples/wordpress-sync-node-id-parity.php` shows scan-time and final sync diffs carrying identical node ids, with changed/added records coming from imported memStore-range shadow leaves and deletes carrying local snapshot node ids.
- `examples/wordpress-sync-shadow-node.php` reports the memStore-range shadow root node id as proof fragments expand toward the authenticated remote snapshot root.
- `examples/wordpress-sync-request-guard.php` demonstrates rejecting overlapping same-path proof fragment requests from a malformed snapshot sync peer before any response proof is exported.
- `examples/wordpress-sync-fuzz-budget.php` runs deterministic upstream-shaped sync-fuzz trials and reports request/response budgets for a Playground snapshot preflight; a separate full 500-trial native probe now passes outside the fast suite.
- `examples/wordpress-persisted-sync-fuzz.php` runs deterministic upstream-shaped sync-fuzz trials while persisting and reloading named tracked heads, then reports restored head continuity, shared tracked nodes, request/response budgets, and authenticated roots for a Playground snapshot preflight. The full 500-trial persisted tracked-node probe now also passes outside the fast suite in 236.484s with the same 25,537 request and 22,591 response budget as the in-memory fuzzer.
- `examples/wordpress-node-id-reuse.php` rebuilds the ordered snapshot from reused leaf node ids, preserving unchanged record node ids while producing the same trusted root and a new branch head id.
- `examples/wordpress-snapshot-fork.php` saves the branch head id for an ordered snapshot, applies a post update on a fork, then checks out both old and new branch heads to read the authenticated record versions.
- `examples/wordpress-node-id-diff.php` compares a saved snapshot with a changed fork and reports matching scan-time and final diff leaf node ids for changed, deleted, and added records.
- `examples/wordpress-tracked-diff-reconstruct.php` applies final tracked diffs to reconstruct a changed WordPress snapshot and shows scan-time node ids matching the final diff node ids.
- `examples/wordpress-memstore-overlay.php` starts from an authenticated ordered snapshot, writes preview-only post changes into upstream's memStore node-id range, and leaves the base snapshot root unchanged.
- `examples/wordpress-named-memstore-fork.php` starts from a named published snapshot head, demonstrates the upstream memStore guard for direct volatile writes, then forks into a detached preview overlay that leaves the published head untouched.
- `examples/wordpress-persisted-node-store.php` exports a named tracked node store to JSON, reloads it, verifies the same published head/root/leaf node ids, then forks a memStore-range preview edit from the restored snapshot.
- `examples/wordpress-quadb-file-store.php` persists the ordered snapshot through native `QuadbStore` integer import lines, reopens the current `preview-snapshot` head from a file-backed directory, and verifies that checking out `master` restores the published post while hiding preview-only records.
- `examples/wordpress-quadb-patch.php` uses tracked string keys to generate upstream-shaped `quadb diff <head>` patch lines for a WordPress preview snapshot, applies them to a replica fork, and verifies that the patched replica root matches the preview root.
- `examples/wordpress-quadb-proof-export.php` exports an upstream-shaped `0x` FullKeys proof from a file-backed WordPress snapshot head, imports it into a native partial tree, and verifies delegated option/post reads plus a proven-absent draft key against the trusted root.
- `examples/wordpress-quadb-proof-import-merge.php` imports a delegated FullKeys proof into an empty file-backed preview head, reopens that proof-backed head, merges a second proof, and verifies persistent authenticated option/post reads without the full snapshot.
- `examples/wordpress-quadb-proof-update.php` imports and forks a delegated FullKeys proof head, applies a persisted preview `siteurl` edit inside the authenticated partial tree, reopens the edited proof head, and exports an updated delegated proof for the new root.
