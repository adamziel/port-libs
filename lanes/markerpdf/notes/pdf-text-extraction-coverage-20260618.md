# markerPDF PDF Text Extraction Coverage - 2026-06-18

This note tracks the native PHP `PdfTextExtractor` safety net for the Playground/Pandoc PDF path. It is not a feature-complete markerPDF claim; it is the current burn-down matrix for searchable-PDF text intake.

## Now Covered

- Page content streams only: non-page streams such as embedded font programs are not promoted into text.
- Page reachability: when a catalog page tree exists, extraction follows `/Catalog` to `/Pages` and nested `/Kids` in tree order instead of scanning stale orphan `/Page` objects.
- Indirect references: non-zero-generation references are mapped to distinct internal objects outside stream payloads, so `/Contents 5 1 R` can resolve separately from stale `5 0 obj` content.
- Classic xref tables: `startxref` and `/Prev` table chains select in-use object byte offsets, skip free entries, and prevent later duplicate object bodies from overriding the xref-selected object. Trailer dictionaries are parsed with balanced dictionary tokenization, so `/Prev` remains visible after nested direct dictionaries such as `/Info << /Producer (...) >>`. Multiple `startxref` markers are parsed, and when a malformed appended update points at an invalid xref offset, extraction falls back to the earlier valid xref section while reporting the malformed offset.
- Xref streams: Flate-compressed `/Type /XRef` streams with direct or indirect `/W` and `/Index` arrays are decoded, including zero-width `/W [0 4 0]` type/generation defaults and nested `/DecodeParms << /Predictor ... >>` dictionaries parsed through balanced stream-dictionary tokenization before PNG predictor decoding. Xref-critical indirect helper lookups are bounded to the current xref revision and prefer the latest matching helper object before that boundary, so stale duplicate `/W`, `/Index`, `/Size`, `/Prev`, and `/XRefStm` helper objects do not misdecode compressed entries or xref chains. Type-1 entries select in-use byte offsets and type-2 entries restrict `/ObjStm` unpacking to live compressed objects. Classic trailer `/Prev`, hybrid trailer `/XRefStm`, and xref-stream `/Size` fallback values can be direct integers or indirect integer objects. Hybrid xref tables merge the associated stream entries over compatibility table entries and follow separate table/xref-stream previous branches. When an encryption context is required first, the extractor builds it from raw objects, retries xref-stream decoding with decrypted stream bytes, and uses the decrypted xref entries to avoid stale duplicate objects. Focused R4 AESV2, R5 AESV3, and R6 AESV3 coverage now combines encrypted xref streams with encrypted object streams, proving decrypted type-2 entries select live packed page/resource dictionaries while stale regular objects are ignored.
