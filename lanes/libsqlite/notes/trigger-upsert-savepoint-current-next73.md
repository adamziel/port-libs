# trigger-upsert-savepoint-current-next73

Status: focused PHP behavior growth for trigger-generated UPSERT rows inside per-row statement savepoints.

This slice adds `SQLiteTriggerUpsertSavepointCurrentNext73Plan`, a bounded native PHP planner for multi-row UPSERT execution where BEFORE/AFTER triggers can mutate NEW rows, recursively UPSERT derived rows, raise IGNORE, or abort only the current row savepoint. The current/next boundary records that committed prior rows and trigger-generated rows advance the WAL frame while failed current rows and their trigger side effects roll back without disturbing earlier changes.

Application smoke: `application-trigger-upsert-savepoint-current-next73.php` models copied `wp_options` import behavior where `siteurl` is rewritten by a BEFORE UPDATE trigger, plugin metadata is generated by an AFTER INSERT trigger, and a blocked plugin option rolls back only its current row.

Non-overlap: this avoids accepted recursive UPSERT savepoint current-next27, trigger RETURNING savepoint current-next65/68, savepoint-trigger rollback current-next20, upsert trigger/FK yield current-next23, WAL byte truncation/savepoint VFS application, rollback-journal commit/apply, JSON table source/cursor/constraints, SELECT SQL text/subquery/group/order, B-tree page/freelist/overflow clusters, VFS lock/sync/write clusters, and Unicode GLOB behavior. The new surface is per-row statement-savepoint rollback for trigger-generated UPSERT side effects while preserving prior current statement changes.

Dependency closure: no new support component is needed. The slice reuses lane-local row-array UPSERT, trigger metadata, and current/next savepoint accounting; it does not require ext/sqlite, shell-out, network, or provider credentials.
